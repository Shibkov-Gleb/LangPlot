# LangPlot

Сервис изучения языков через интерактивные истории. В [English A2](http://localhost:3000/courses/en/a2) доступны все 90 уроков «Последней переклички», оба пути 31–45 и три развязки. Прогресс, решения и переписки сохраняются. После урока можно открыть теорию, продолжить сюжет или начать отдельную попытку. После финала доступна короткая сверка ошибок из журнала. Телефон поддерживает живую переписку DeepSeek и локальный режим для проверок.

## Запуск на сервере

На Linux-сервере нужны Docker и Git. Выполните `./langplot init ваш-домен.ru`, добавьте ключ DeepSeek в созданный `.env`, затем `./langplot deploy`. Обновления — `./langplot update`: сборка, резервная копия, миграции и проверка готовности выполняются автоматически. Перенос — `./langplot transfer` и `./langplot restore архив` на новом сервере. [Короткая инструкция](docs/DEPLOYMENT.md) описывает сохранение данных, перенос и диагностику. Прежний `.env.production` также поддерживается.

## Быстрый локальный запуск

Нужны **Node.js 22**, **pnpm 10.28.2**, Docker Desktop с запущенным Linux-движком. Проверяйте `node --version` и `pnpm --version`: некоторые оболочки подставляют собственный Node. Версии библиотек и lockfile закреплены.

В PowerShell из корня репозитория:

```powershell
# Если pnpm ещё не установлен:
npm install --global pnpm@10.28.2

# Только при первой настройке, чтобы не перезаписать свои параметры:
Copy-Item .env.example .env
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:up
pnpm db:migrate
pnpm dev
```

Откройте [LangPlot](http://localhost:3000) и нажмите «Выбрать язык». Можно создать аккаунт, войти в существующий или пройти весь первый урок «Последний ряд» без регистрации. Гостевое прохождение возобновляется в том же браузере. После финальной переписки создайте аккаунт или войдите в существующий, чтобы сохранить решения, ответы и сообщения.

- Next.js: `localhost:3000`, слушает loopback.
- Express: `127.0.0.1:4000`; браузер обращается к нему через Next `/api`.
- PostgreSQL: `127.0.0.1:55432`, постоянный Docker volume `langplot-data`.
- `GET /api/health` проверяет и сервер, и подключение к базе.
- `pnpm db:down` останавливает контейнер, **сохраняя данные**.

Интернет нужен для первоначальной установки пакетов и Docker-образа. Пользовательские сценарии приложения работают локально. Картинки и шрифты включены в проект/зависимости и обслуживаются тем же сервером.

На текущем компьютере системная обёртка `pnpm` выбирает другой Node. Для воспроизводимого запуска в каждом новом терминале PowerShell используйте установленный локально pnpm:

```powershell
# Уже установлено в этой рабочей папке; для новой копии репозитория:
npm install --prefix .local/tools pnpm@10.28.2 --ignore-scripts --no-audit --no-fund
$env:PATH = "C:\Program Files\nodejs;$PWD\.local\tools\node_modules\.bin;$env:PATH"
node --version # 22.x
pnpm --version # 10.28.2
```

## Если Docker не запускается на этом Windows-компьютере

При реализации Docker Desktop завершался с таймаутом DNS `host.docker.internal`. Повреждённый старый сокет его Inference-модуля был устранён, настройки Docker возвращены к исходным. Сетевые настройки системы не менялись. Compose подготовлен, но запуск контейнера в этой среде не подтверждён.

Для рабочего просмотра и тестов использован отдельный PostgreSQL **17.7** в `.local`, с тем же протоколом, портом и миграциями. Резервный путь не меняет архитектуру приложения. Суффикс beta относится к npm-обёртке бинарного дистрибутива.

```powershell
npm install --prefix .local/postgres @embedded-postgres/windows-x64@17.7.0-beta.16 --ignore-scripts --no-audit --no-fund
pnpm db:generate
pnpm db:local
```

Оставьте этот терминал открытым. Во втором:

```powershell
pnpm db:migrate
pnpm dev
```

`db:local` создаёт `.local/pgdata-local` и базу `langplot` при первом запуске. Повторный запуск сохраняет данные. Завершение — Ctrl+C. Не запускайте одновременно Docker-базу и резервную базу на одном порту. Это **разные хранилища данных**: автоматического переноса между ними нет.

Порт 55432 выбран потому, что 54329 на этой машине входит в диапазон, зарезервированный Windows/Hyper-V. Не меняйте системные резервирования ради приложения.

## Что проверить в интерфейсе

1. На главной — языковые миры, анимации появления, FAQ и переход в кабинет.
2. В «Моих мирах» выберите язык и нажмите на уровень. [English A2](http://localhost:3000/courses/en/a2) открывает список уроков «Последней переклички». У завершённого урока доступны повторное прохождение и теория. Вся открытая теория также хранится в [материалах](http://localhost:3000/dashboard/materials).
3. В «Настройках» — имя, родной язык, звук, субтитры и уменьшение анимации. Озвучка персонажей уже доступна в курсе A2.
4. В «Настройках» можно бесплатно активировать тестовую подписку. Ученики с обоими статусами проходят один и тот же курс.
5. В карточках других уровней и немецкого направления отображается «В разработке». Игровой экран открывается из урока A2.

## Доступ к администрированию

На компьютере с базой выполните `pnpm admin:invite` после миграции. Откройте адрес из `.local/admin-invite.txt` в браузере и создайте аккаунт главного администратора. Ссылка действует 24 часа, используется один раз. Повторная команда заменяет старую ссылку, пока главный администратор ещё не создан. Файл приглашения исключён из Git.

В [администрировании](http://localhost:3000/admin) доступны поиск по имени и почте, фильтры ролей и статусов, список контактов на сегодня и просроченных контактов. Откройте карточку ученика, чтобы посмотреть последние занятия, оставить внутреннюю заметку или назначить дату контакта. Изменения записываются в историю с автором и датой.

| Доступ                | Возможности                                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Без подписки          | Курс A2, сохранения, материалы, профиль и тестовое подключение подписки                                                            |
| С подпиской           | Те же учебные возможности                                                                                                          |
| Администратор         | Учебный кабинет, CRM, студия, создание и импорт черновиков                                                                         |
| Главный администратор | Все возможности администратора, задания студии всех администраторов, назначение и снятие административных прав в карточке аккаунта |

После снятия прав восстанавливается статус подписки ученика. Права API проверяет по базе при каждом запросе. Общий демо-профиль и его прежние прохождения сохраняются в базе отдельно от личных аккаунтов. Миграция завершает прежние демо-сессии.

## Команды и проверки

```powershell
pnpm typecheck
pnpm test
pnpm test:api
pnpm build
pnpm format:check

# Локальный просмотр собранного frontend (при запущенной базе):
pnpm preview

# Браузерные тесты: сначала запустите pnpm dev или pnpm preview
pnpm exec playwright install chromium --no-shell
pnpm test:e2e
```

API-тесты применяют миграции к отдельной временной схеме `langplot_test_<uuid>` в PostgreSQL, затем удаляют только эту схему. Демо-данные приложения они не затрагивают. Для отдельной тестовой базы можно задать `TEST_DATABASE_URL`. Браузерные проверки создают временные аккаунты и удаляют их после сценария.

Для полного набора браузерных проверок с фиксированными ответами запустите приложение с `CHAT_PROVIDER=local` в окружении терминала. Проверка `tests/e2e/character-chat.spec.ts` включает отдельный живой сценарий с `LIVE_DEEPSEEK=1`. Он использует DeepSeek на запущенном сервере и требует ключ.

Браузерные проекты: 375, 768 и 1440 px; проверяются отсутствие горизонтального переполнения, сохранение выбора/настроек, телефон, экспорт/импорт, клавиатура и `prefers-reduced-motion`. Скриншоты находятся в `test-results/`, HTML-отчёт — в `playwright-report/`.

На текущем Windows скачанный Chromium не стартовал из-за ошибки side-by-side configuration. Проверки выполняются в установленном Edge:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
pnpm test:e2e
```

Установленный антивирус внедряет собственные запросы к `me.kis.v2.scr.kaspersky-labs.com`. Тест сетевой автономности исключает только этот известный внедрённый адрес, не отключая антивирус. Другие внешние запросы считаются ошибкой.

## Конфигурация и следующий этап

`.env.example` содержит все параметры. `dev` и `preview` передают их обоим приложениям. `PORT` задаёт порт Express; порт frontend берётся из `WEB_PORT`, затем `WEB_ORIGIN` (по умолчанию 3000), интерфейс — из `WEB_HOST` (по умолчанию loopback). При изменении портов согласованно обновляйте команды frontend, `PORT`, `API_ORIGIN` и `WEB_ORIGIN`; после изменения `API_ORIGIN` пересоберите frontend. Секреты в браузер не передаются. `.env`, `.local`, сохранения и результаты тестов исключены из Git.

`CHAT_PROVIDER=local` и `COURSE_PROVIDER=local` включают тестовые реализации; значение `none` возвращает понятный статус «Не настроено». `TTS_PROVIDER=gemini` обозначает подготовку озвучки через Gemini. Внешняя трассировка LangSmith отключается на сервере независимо от унаследованного окружения.

Для живой переписки задайте `CHAT_PROVIDER=deepseek` и `DEEPSEEK_API_KEY` в локальном `.env`. Поддерживается также имя ключа `DEEPSEEK_API`. Модель задаётся через `DEEPSEEK_MODEL`, по умолчанию используется `deepseek-flash`. Команды запуска API используют доверенное хранилище сертификатов ОС через Node.js `--use-system-ca`. Запуск проверен на Node.js 22.19.

Сервер передаёт модели уровень курса, текущего собеседника, его известные факты, увиденные игроком реплики этого собеседника, тему телефона и последние десять обменов текущего прохождения. Имя и почта аккаунта в запрос не включаются. Отдельная проверка модели оценивает ответ по контексту и уровню. Ответ содержит от одного до трёх коротких сообщений. При отклонении ответа персонаж возвращает разговор к текущей теме. Игровые решения проверяет сервер. Переписка и границы сообщений сохраняются в PostgreSQL, а прежние записи с одним ответом продолжают отображаться. Таймаут, отмена и повторная отправка сохраняют исходный идентификатор сообщения.

Для подготовки реплик English A2 добавьте `GEMINI_API_KEY` в локальный `.env`. Поддерживаются также имена `GEMINI_API` и `GOOGLE_API_KEY`. Ключ читает локальная команда генерации. Пользовательский плеер получает готовые MP3 с сервера LangPlot. Голоса десяти персонажей задаются в `content/courses/en-a2-voices.json`.

```powershell
npm install --prefix .local/audio-tools ffmpeg-static@5.2.0 --no-audit --no-fund
pnpm tts --dry-run
pnpm tts --batch
```

Можно указать `FFMPEG_PATH` вместо установки локального инструмента. `--batch` отправляет массовую подготовку в Batch API Google и дожидается результатов. Состояние заданий сохраняется в `.local/tts`. Повторный запуск продолжает существующие задания. Для отдельных реплик используйте `pnpm tts --lesson=last-row --concurrency=3`. `--limit=10` ограничивает число новых реплик. Готовые файлы используются повторно. Изменение текста или голоса требует новой генерации соответствующих реплик. Индекс и MP3 сохраняются в `apps/web/public/assets/voices/en-a2`. Неудачные строки пакетного задания повторяются отдельно. API подхватывает обновления индекса, а текст старых сохранений сопоставляет с озвучкой по точному содержимому. После добавления файлов в production-режиме перезапустите `pnpm preview`, чтобы Next.js обновил список ресурсов.

Серверная конфигурация рассчитана на **один процесс Express**. Следующие этапы: педагогическая модель персонализации и общая очередь фоновых задач для нескольких экземпляров API. Публикация курсов намеренно ещё не подключена. Интерфейсы LLM, TTS и файлового хранилища подготовлены для заменяемых реализаций.

## Аналитика и локальное сравнение

В администрировании откройте «Обзор», «Уроки» или «Ученики». Периоды и дни удержания привязаны к Москве. Для посещения источник берётся из `utm_source`, затем из домена внешнего перехода или `direct`. На экране уроков период относится к датам учебных действий. На обзоре — к дате первого посещения браузера. Исторические действия восстановлены по версиям контента и событиям сохранения. Исторические посещения не реконструируются.

Тестовая подписка имеет собственный показатель. При подключении реального провайдера доверенный обработчик проверенного подтверждения вызывает `confirmFirstPayment`; до этого `PAYMENTS_ENABLED=false`. Выгрузка по когортам имеет одну строку на день и показатель. Данные сегментов и уроков доступны обеим административным ролям. Контактный файл скачивает главный администратор, скачивание фиксируется в PostgreSQL. Предпросмотр фиксирует состав файла на две минуты.

Ветка `main` работает с `UI_VARIANT=original`, `WEB_ORIGIN=http://localhost:3000`, `API_ORIGIN=http://127.0.0.1:4000`, `PORT=4000`. Для второго checkout используйте `UI_VARIANT=first-scene`, `WEB_ORIGIN=http://localhost:3001`, `API_ORIGIN=http://127.0.0.1:4001`, `PORT=4001` и тот же DATABASE_URL. В каждом checkout доступны `pnpm dev` или `pnpm build` и `pnpm preview`. Для локальных тестовых браузеров применяется заголовок `X-LangPlot-QA: 1`; в production он не позволяет исключить события из аналитики. Original и first-scene используют разные cookie на одном хосте.
