# Подготовка пакетов через Codex и API

Пакеты — декларативные JSON. Версии 1–3 поддерживают прежние черновики и уроки. Версия 4 добавляет варианты места и телефона, экспорт сюжетных фактов и компактный банк повторения. Все 105 вариантов сезона English A2 находятся в `content/lessons/`.

## Локальный процесс

1. Создайте новый файл в `content/drafts/`. Не меняйте ранее импортированную версию.
2. Задайте уникальный `manifest.id`, semver `manifest.version`, `language` (`en` / `de`), `level` (`A1`–`C2`), `status: draft`.
3. Выполните из корня `pnpm content validate ../../content/drafts/my-package.json`. Команда работает из `apps/api`, поэтому пути относительно неё. Также можно передать абсолютный путь.
4. При необходимости проверьте готовность: `pnpm content validate ../../content/drafts/my-package.json --publish`. Пустой пакет должен завершиться с ненулевым кодом.
5. Импортируйте через локальную студию или `pnpm content import ../../content/drafts/my-package.json`. Для импорта нужны запущенная PostgreSQL, миграции и `LOCAL_DEMO_MODE=true`.

API студии и CLI используют одни и те же `validatePackage` и `importPackage`. Граф LangGraph использует тот же валидатор. Дубликат `(manifest.id, manifest.version)` отклоняется; увеличивайте версию. Прохождения остаются привязаны к прежней версии.

## Уроки курса и теория

Страница курса читает порядок глав из `content/courses/catalog.json`. У будущего урока укажите номер и название. Когда игровой пакет готов, замените название на `slug`, который совпадает с именем файла `content/lessons/<slug>.json`. Язык и уровень манифеста должны совпадать с курсом.

Справочник использует все записи `lesson.notes` пройденной версии, включая слова из альтернативных сцен. Для слова укажите контекстный перевод, для правила — объяснение. Можно задать `example` явно. Если его нет, справочник использует размеченное предложение урока. Повторное прохождение сохраняет доступ к справочнику.

## Формат

Расширенный справочник English A2 хранится отдельно в `content/courses/en-a2-study-guide.json` и проверяется общей схемой `StudyGuide`. `grammar` содержит статьи с объяснениями, таблицами, переведёнными примерами, частыми ошибками и самопроверкой. В `lessons` каждый из 105 пакетов ссылается на изучаемые `grammarKeys` и перечисляет общие темы `vocabulary`; у глав с повторением это указано явно. Темы видны в каталоге до начала игры, а статьи открываются после завершения урока. Для путей D/F заполняются обе записи.

Справочник можно дополнять независимо от игровых версий: завершённые попытки, реплики и исходные заметки остаются неизменными, а страница теории получает актуальную расширенную статью по ключу правила. Для старого или другого курса без статьи продолжает работать краткое пояснение из пакета. Изменение самих игровых правил и реплик по-прежнему требует новой версии манифеста.

У записи курса 31–45 поле `routes` содержит два пакета с метками `D` и `F`. Каждый путь имеет собственные попытки и теорию. Переход к следующему уроку сохраняет выбранный путь. При переносе решений учитываются завершённые попытки текущего пути.

В версии 4 `lesson.initialFlags` задаёт свойства конкретного пути, `exportFlags` перечисляет дополнительные факты для следующих глав. `phoneVariants` выбирает адресата, первые сообщения и фиксированный ответ по сохранённому флагу. `settingVariants` меняет фон и вступление, когда доступ к месту зависит от обещания.

`reviewTemplates` хранит исходную фразу, варианты и реакцию на ошибку для каждого изученного навыка. Движок создаёт из них короткие сцены `review.<skill>` при наступлении срока повторения. Банк входит в неизменяемую версию пакета. После 90-го урока отдельная попытка `review.only` даёт до двух реконструкций и возвращает к финальному экрану. Финальное прохождение и его переписка сохраняются.

В версии 3 блок `lesson` содержит `decisionFlag`, два `openings`, `carryFlags`, роль контакта, контекст телефона и `presentation` с местом, временем и названием финального экрана. Вместо полей билета используются общие поля решения. `caption` сцены содержит русскую постановку или инструкцию задания. Служебная сцена `branch` автоматически выбирает один из двух переходов по значению флага. Проверка достижимости учитывает переход от контрольной сцены к заданиям повторения.

При создании попытки сервер копирует в неё перечисленные `carryFlags` из последних завершённых предыдущих уроков того же курса. Для известного решения добавляется `known.<flag>`. Начатое прохождение сохраняет этот снимок. Переигровка получает актуальные прежние решения, а история завершённой попытки остаётся доступной. При прямом входе в пятый урок предусмотрена сцена с пробным билетом, если первый рейс ещё не завершён.

Новое повторное прохождение использует текущую версию урока. Исходная попытка, её сообщения и справочник сохраняют прежнюю версию. Послесезонная сверка использует актуальный банк повторения с сохранением сюжетного результата.

- `schemaVersion`: `1` для базовых пакетов. Версия `2` добавляет блок `lesson` с текстами входящего телефона, указателями сцены повторения и словарём подсказок. Сцены описывают оформление, привязанные к тексту фрагменты и, при необходимости, варианты упражнения, правильный переход и реакцию на ошибку. Локальные ресурсы урока поставляются вместе с сайтом. При изменении уже импортированного урока повышайте версию манифеста.
- `manifest`: ID, версия, название, описание, язык, уровень, статус.
- `entrySceneId`: ID стартовой сцены; `null` в пустом каркасе.
- `characters`: `id`, `name`, `knownFacts`. Модель видит только разрешённые факты собеседника.
- `learningObjectives`: `id`, `description` — допустимые идентификаторы учебных наблюдений.
- `resources`: `id`, `path`, `mediaType`. Только относительные пути `assets/...` и расширения `webp/png/jpg/mp3/wav/woff2`. Никаких URL, абсолютных путей, `..`, SVG, JS, HTML или архивов.
- `scenes`: `id`, `text`, необязательные `speakerId` и `resourceId`, `terminal`, `objectiveIds`, `choices`.
- `choices`: `id`, `label`, `target`, необязательное условие `{ "flag": "flag.id", "equals": true }`, `setFlags` с булевыми значениями и необязательный `journalEntry`.

Идентификаторы содержат строчные латинские буквы, цифры, `._-`, начинаются с буквы и не длиннее 80 символов. Условия ограничены проверкой одного булева флага; запрещены eval, функции, скрипты, произвольные выражения и вызовы сети. Несуществующие ссылки, повторяющиеся идентификаторы и недостижимые сцены отклоняются.

Импорт пока принимает только JSON до 1 МБ. Бинарные ресурсы не загружаются: ссылки проверяются, но наличие файлов не подтверждается. Публикация пакета с неподтверждёнными ресурсами запрещена. Серверная публикация пока отключена даже для полного пакета — потребуется отдельный редакторский процесс.

## Подключение новых механик

Обычные главы добавляются пакетами без обновления приложения. Новое поле состояния, тип задания или условие требует новой версии схемы, изменения общего движка, миграции при необходимости и тестов. Нельзя обходить валидатор, чтобы добавить произвольную логику в JSON.

Локальный провайдер возвращает только каркас. Будущий API-провайдер должен реализовать `CourseProvider`, а модель переписки — `ChatProvider`. Не добавляйте ключи в пакеты, браузерный код или Git. Внешняя трассировка отключена. Публичные провайдеры подключаются отдельно, после определения размещения и правил обработки данных.
