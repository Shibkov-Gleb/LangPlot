# LangPlot на Linux-сервере

Конфигурация `compose.production.yaml`: Caddy принимает HTTPS, Next.js отдаёт сайт и готовые изображения/озвучку, Express обрабатывает API, PostgreSQL хранит аккаунты, прогресс, сообщения и CRM. Публичные порты — только 80 и 443. Для клиентских данных и резервных копий выберите размещение в России. Дизайн сайта остаётся прежним.

Локальные `.env`, `compose.yaml`, база на 55432 и `pnpm dev` используются отдельно для разработки.

## Первый запуск

Нужны Linux, Docker Engine с Compose v2, Git, домен с A/AAAA-записями на сервер и открытые TCP 80/443. UDP 443 используется для HTTP/3. Без IPv6 не добавляйте AAAA-запись. Сборке нужен доступ к Docker Hub, npm и пакетам Debian, работающему API — к DeepSeek. Браузер обращается только к домену LangPlot.

Скопируйте репозиторий или выполните `git clone`, перейдите в его корень. Все команды выполняются оттуда. Создайте **отдельное серверное окружение**:

```bash
node scripts/init-production.mjs learn.example.ru
```

Требуется Node.js 22. Если на сервере установлен только Docker:

```bash
docker run --rm --user "$(id -u):$(id -g)" \
  -v "$PWD:/work" -w /work node:22-bookworm-slim \
  node scripts/init-production.mjs learn.example.ru
```

Создаётся `.env.production` с новым случайным паролем PostgreSQL и правами `600`. Существующий файл не перезаписывается. Откройте файл редактором, заполните `DEEPSEEK_API_KEY`, проверьте `DOMAIN` и `WEB_ORIGIN`. Домен указывается без схемы, origin — с `https://` и без пути. Не копируйте локальный `.env` целиком. Окружение исключено из Git и Docker-образов.

`APP_TAG` обозначает выпуск. Генератор берёт Git-хеш; без доступного Git ставит `local`. Замените его уникальным именем выпуска, например результатом `git rev-parse --short=12 HEAD`. Сгенерированный пароль использует безопасные для URL шестнадцатеричные символы. После создания тома изменение `POSTGRES_PASSWORD` в файле само по себе не меняет пароль существующей базы.

```bash
docker compose --env-file .env.production -f compose.production.yaml config --quiet
docker compose --env-file .env.production -f compose.production.yaml build
docker compose --env-file .env.production -f compose.production.yaml up -d --wait
docker compose --env-file .env.production -f compose.production.yaml ps -a
```

Одноразовый контейнер `migrate` выполняет `prisma migrate deploy`: состояние `Exited (0)` означает успех. API ждёт миграции, сайт — готовности API. Caddy получает и обновляет HTTPS-сертификат домена. Откройте сайт и `/api/health`: ожидается `{"ok":true,"localMode":false}`.

Для проверки без запросов к модели можно явно выбрать `CHAT_PROVIDER=local` — ответы будут тестовыми. Для пользовательского запуска верните `deepseek` и задайте ключ; при его отсутствии API откажется запускаться. Готовые MP3 входят в образ сайта: Gemini-ключ для воспроизведения не нужен.

## Главный администратор

```bash
docker compose --env-file .env.production -f compose.production.yaml exec api \
  node apps/api/dist/owner-invite.mjs
docker compose --env-file .env.production -f compose.production.yaml exec api \
  cat /app/var/admin-invite.txt
```

Откройте ссылку лично и зарегистрируйтесь. Она действует 24 часа и принимается один раз. Файл находится в закрытом томе API; ссылка не выводится в журналы запуска. После настройки главного администратора повторная команда отказывает. Остальным администраторам права назначаются в CRM. Студия и импорт доступны только административным ролям. Демо-вход в production отключён независимо от `LOCAL_DEMO_MODE`.

## Постоянные данные

| Том                          | Содержимое                                                             |
| ---------------------------- | ---------------------------------------------------------------------- |
| `postgres-data`              | Аккаунты, сессии, прогресс, версии контента, сообщения, CRM, аналитика |
| `api-data`                   | Закрытое первоначальное приглашение                                    |
| `web-cache`                  | Пересоздаваемый кэш изображений Next.js                                |
| `caddy-data`, `caddy-config` | Сертификаты и состояние HTTPS                                          |

Полные имена начинаются с `langplot-production_`. `docker compose ... down` сохраняет тома. **Не используйте `down -v` для рабочего проекта**: это удаляет данные.

## Резервная копия и восстановление

```bash
node scripts/backup-production.mjs
# Или каталог на подключённом диске:
node scripts/backup-production.mjs /srv/langplot-backups
```

Создаётся консистентный бинарный дамп работающей базы. Скрипт сначала пишет `.tmp`, переименовывает его после успеха, задаёт права `600` и возвращает ненулевой код при ошибке. Он работает и в Windows, без преобразования бинарных данных PowerShell в текст.

На Linux без Node можно выполнить:

```bash
mkdir -p backups
umask 077
docker compose --env-file .env.production -f compose.production.yaml exec -T postgres \
  sh -c 'exec pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' \
  > "backups/langplot-$(date -u +%Y%m%dT%H%M%SZ).dump"
```

Поставьте резервное копирование в расписание и сохраняйте копию вне диска приложения в выбранном российском хранилище. Защитите также `.env.production`, сохраните код/образы нужного выпуска: медиа и каталог входят в образы, а не в дамп. Резервные копии содержат пользовательские данные; не публикуйте их через сайт.

Для проверки восстановления:

```bash
node scripts/restore-production.mjs backups/имя-файла.dump langplot_restore_20261112
docker compose --env-file .env.production -f compose.production.yaml exec postgres \
  sh -c 'psql -U "$POSTGRES_USER" -d langplot_restore_20261112'
```

Скрипт создаёт **новую** базу с префиксом `langplot_restore_`. Если имя занято, команда отказывает; текущая база остаётся прежней. После ошибки частично восстановленная новая база остаётся для диагностики: для повтора выберите новое имя. В `psql` проверьте, например, `SELECT count(*) FROM "User";`, выйдите через `\q`.

Для перехода на восстановленную базу остановите `api web caddy`, сохраните прежнее окружение, измените `POSTGRES_DB` на новое имя и выполните `up -d --wait`. Миграции применятся перед API. Прежняя база сохранится. Проверьте вход, продолжение урока и CRM. До пользовательского запуска проверьте восстановление также на отдельном сервере.

На Linux без Node те же действия можно выполнить вручную:

```bash
docker compose --env-file .env.production -f compose.production.yaml exec -T postgres \
  sh -c 'exec createdb -U "$POSTGRES_USER" --template=template0 langplot_restore_20261112'
docker compose --env-file .env.production -f compose.production.yaml exec -T postgres \
  sh -c 'exec pg_restore -U "$POSTGRES_USER" -d langplot_restore_20261112 --no-owner --no-acl --exit-on-error' \
  < backups/имя-файла.dump
```

Выполняйте вторую команду только после успешного создания новой базы. Всегда восстанавливайте сначала в новую базу.

## Перенос локальной базы

Для чистого запуска перенос не нужен: курс A2 приложение читает из поставляемых пакетов. Если нужны существующие аккаунты и прохождения, сделайте дамп локальным `pg_dump` версии 17 или новее. Используйте `--file`, чтобы исключить текстовое перенаправление Windows:

```powershell
pg_dump --host=127.0.0.1 --port=55432 --username=langplot --dbname=langplot --format=custom --file=langplot-local.dump
```

Пароль введите по запросу. Передайте дамп на сервер по защищённому каналу, восстановите в отдельную базу и переключите `POSTGRES_DB`, как описано выше. Проверьте перенесённые тестовые аккаунты. Уже существующий главный администратор сохраняет пароль и права; новое приглашение ему не требуется.

## Обновление и возврат выпуска

1. Создайте резервную копию, запишите текущий `APP_TAG` и коммит.
2. Получите проверенный коммит, установите новый уникальный `APP_TAG`.
3. Выполните `build`, затем `up -d --wait`. Миграции запускаются автоматически. При обновлении возможна короткая остановка.
4. Проверьте здоровье API, вход, продолжение урока, озвучку и CSV в администрировании.

Для возврата к сохранённым образам задайте предыдущий `APP_TAG` и выполните `up -d --no-build --wait`. Старая версия кода должна быть совместима с применёнными миграциями. Для несовместимой схемы восстановите предшествующий дамп в отдельную базу и переключите её вместе с кодом. Автоматического отката схемы нет. Не пересобирайте старый тег из нового кода.

Новый курс/озвучка в репозитории попадают на сервер после сборки выпуска. Черновики студии хранятся в PostgreSQL. Публикация курсов и реальные оплаты остаются отдельными будущими этапами.

## Диагностика и ограничения

```bash
docker compose --env-file .env.production -f compose.production.yaml logs --tail=100 api web migrate caddy
docker compose --env-file .env.production -f compose.production.yaml restart api
```

Журналы Docker ограничены тремя файлами по 10 МБ на сервис. API запускается обычным Node из ESM-сборки, сайт — из Next.js standalone. Инструменты разработки и `.env` им не нужны. Приложения работают от непривилегированного пользователя: запись разрешена в нужные тома и `/tmp`. Остановка API ждёт активные HTTP-запросы; после аварийного перезапуска незавершённые переписки и задания получают статус с возможностью повтора.

Схема рассчитана на **один экземпляр API**: лимиты запросов, контроллеры отмены и исполнитель студии пока находятся в памяти процесса. Для нескольких API потребуются общая очередь, лимитирование и координация заданий. Если добавите CDN/балансировщик, отдельно настройте доверенную цепочку прокси: `TRUST_PROXY=1` сейчас относится к Caddy → Express. Caddy заменяет клиентский `X-Forwarded-For` адресом соединения и удаляет служебный QA-заголовок. PostgreSQL не публикуется в Интернет.

Для изолированных проверок скрипты копирования поддерживают `LANGPLOT_ENV_FILE` и `COMPOSE_PROJECT_NAME`. Обычному серверному запуску они не нужны.
