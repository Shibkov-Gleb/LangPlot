# LangPlot: запуск, обновление и перенос

На Linux-сервере нужны **Docker Engine с Compose v2, Git и Bash**. Node.js, pnpm и PostgreSQL устанавливать на сервер отдельно не требуется. `flock` из стандартного пакета `util-linux` защищает от одновременных операций. Домен должен указывать на сервер; откройте TCP 80/443 и, при использовании HTTP/3, UDP 443. Для данных пользователей и резервных копий выберите размещение в России.

## Первый запуск: две команды и ключ

Склонируйте репозиторий, перейдите в его папку:

```bash
./langplot init learn.example.ru
nano .env
# Вставьте DEEPSEEK_API_KEY и сохраните файл.
./langplot deploy
```

Если скопировали файлы без прав исполнения, используйте `bash ./langplot ...`. `init` сам создаёт пароль PostgreSQL, HTTPS-адрес и имя проекта. Существующий файл не перезаписывается. На сервере с прежним `.env.production` он будет использован автоматически; ключ можно дописать туда. Для явного выбора: `LANGPLOT_ENV_FILE=.env.production ./langplot deploy`. Не используйте локальный разработческий `.env` вместо серверного.

`deploy` проверяет настройки, собирает образы, запускает PostgreSQL, применяет миграции, ждёт готовности API/сайта и включает HTTPS. Тег выпуска назначается автоматически. Для первого главного администратора выполните `./langplot owner` и откройте одноразовую ссылку. На последующих запусках аккаунт владельца сохраняется.

## Обновление: одна команда

```bash
./langplot update
```

Команда получает обновления текущей ветки через `git pull --ff-only` и выполняет деплой. Незакоммиченные изменения не перезаписываются. Если код уже обновлён вручную или получен без Git, используйте `./langplot deploy`.

Порядок обновления:

1. Новые образы собираются, пока работает прежний сайт. Ошибка сборки не останавливает его.
2. Включается страница обслуживания с HTTP 503; текущие запросы завершаются, запись останавливается.
3. Создаётся полный архив в `backups/`. При ошибке копирования миграции не запускаются.
4. Применяются миграции, запускаются и проверяются новые контейнеры.
5. Сохраняется номер выпуска, сайт снова открывается.

Повторные сборки используют кэш зависимостей. API и frontend собираются раздельно; изменение документов, скриптов управления или готовых MP3 не требует повторной компиляции всего приложения. При обновлении будет короткое окно обслуживания. Это не схема обновлений без остановки.

## Где сохраняются данные

Аккаунты, хеши паролей, сессии, решения, попытки, переписки, CRM и аналитика хранятся в томе PostgreSQL. Постоянные файлы API — в отдельном томе. Их имена привязаны к `LANGPLOT_PROJECT_NAME`, по умолчанию `langplot-production`, и не зависят от имени папки с кодом. Обновление заменяет контейнеры, сохраняя тома. `.env` с ключами и паролем базы остаётся на сервере.

После первого запуска не меняйте `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` и `LANGPLOT_PROJECT_NAME` для обычного обновления: автоматизация обнаружит смену и остановится. Ключ DeepSeek менять можно. Команды управления не удаляют тома. Не выполняйте `docker compose down -v` для рабочего проекта.

## Резервная копия: одна команда

```bash
./langplot backup
```

Результат — один `backups/langplot-....tar.gz` с:

- консистентным дампом всей PostgreSQL, включая версии контента и сессии;
- постоянными файлами API;
- версией формата, сведениями о миграциях и SHA-256 файлов.

Ключ DeepSeek и пароль PostgreSQL в архив не включаются. Новая база на новом сервере получит отдельный пароль; пароли аккаунтов и прогресс сохраняются из дампа. Архив имеет права `600`, содержит пользовательские данные и должен храниться закрыто. Копия на том же диске не защищает от потери сервера: регулярно переносите архивы в отдельное выбранное хранилище. Скрипт не удаляет старые копии автоматически.

Обычный `backup` не останавливает пользователей: дамп отражает согласованный снимок PostgreSQL. Для финального переноса используйте `transfer`, чтобы исключить новые записи после копии. Текущие постоянные файлы API занимают мало места; формат ограничивает их суммарный размер 48 МиБ и не принимает символические ссылки. При появлении пользовательских загрузок большего размера потребуется отдельная стратегия файлового хранилища. Готовые сцены, иллюстрации и MP3 поставляются с кодом/образами; переносите совместимую версию проекта.

## Перенос на другой сервер

**На прежнем сервере:**

```bash
./langplot transfer
# Команда напечатает путь финального архива.
scp backups/имя-архива.tar.gz user@новый-сервер:/папка/LangPlot/backups/
```

`transfer` оставляет прежний сайт в режиме обслуживания, API — остановленным. Архив включает последние завершённые действия. Режим обслуживания сохраняется после перезапуска Caddy. Не возобновляйте запись на прежнем сервере одновременно с новым.

**На новом сервере:** склонируйте совместимую версию проекта, положите архив в `backups/` и выполните:

```bash
./langplot init learn.example.ru
nano .env
# Вставьте DEEPSEEK_API_KEY.
./langplot restore backups/имя-архива.tar.gz
```

`restore` проверяет структуру и контрольные суммы архива, совместимость миграций, собирает образы, восстанавливает новую базу и постоянные файлы, сверяет число записей финального снимка и запускает приложение. Старые пользовательские идентификаторы, хеши паролей и сохранения остаются прежними. С существующими томами команда отказывает: рабочую базу нельзя случайно перезаписать.

После проверки переключите DNS на новый сервер. Для публичного HTTPS сертификата DNS и порты должны быть доступны; до переключения DNS выпуск сертификата на новом сервере может ожидать подтверждения. Старый сервер храните вместе с архивом до завершения проверки. Для отмены переноса до открытия нового сервера: `./langplot resume`. Для остановки уже выведенного из эксплуатации сервера: `./langplot stop` — тома сохранятся.

## Если что-то пошло не так

```bash
./langplot status
./langplot logs
```

Этап, выпуск и путь предшествующей копии сохраняются в `.local/server/`. Если ошибка произошла после остановки записи или при миграциях, сайт остаётся в обслуживании. База и копии не удаляются. Откат схемы или замена данных старой копией автоматически не выполняются: это могло бы скрыть ошибку или потерять новые записи.

После исправления причины повторите `./langplot deploy`. Для восстановления из копии используйте чистый сервер/новый изолированный проект, проверку и последующее переключение. Старые данные оставьте для проверки. Если перенос просто отменён и миграции не менялись, используйте `./langplot resume`.

Существующие ручные команды и дампы `.dump` поддерживаются: [расширенная инструкция](DEPLOYMENT_MANUAL.md). Обычный рабочий сценарий — команды `./langplot`. Не запускайте несколько экземпляров API: текущая очередь студии и контроллеры отмены рассчитаны на один процесс.
